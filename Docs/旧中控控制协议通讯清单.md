## 1. 结论摘要

- 原 UI 设计基准分辨率为 `2800 × 1840`。
- 旧控制通讯没有被删除，相关脚本、设备配置、继电器报文和红外学习码仍保存在工程中。
- `level0` 运行时会自动连接旧现场 TCP 设备：
  - 继电器/控制器：`192.168.86.80/81/82/85/86:10000`
  - 红外模块：`192.168.86.90/91:502`
- `level0` 中还启用了 UDP 控制、FMNetwork 服务端和网络唤醒组件。
- 串口、Socket.IO、网络发现等代码存在，但当前 `level0` 未直接挂载；其中部分组件可能在运行时动态创建。
- 当前配置同时出现 `192.168.86.x`、`192.168.20.x`、`192.168.3.x`、`192.168.1.x` 四个网段，包含实际旧现场参数和通用控制器模板参数，不能直接作为新现场地址使用。

## 2. 通讯架构

```text
level0 UI Toggle/Button
        │
        ├─ FirstPageEquipManager ─ EventCenter ─ TcpControl80/81/82/85/86
        │                                      └─ TcpControl90/91
        │
        ├─ SoftWareManager ─ 动态创建 UDPClient / UDPClient2
        │                 └─ ASCII 文本命令或十六进制设备命令
        │
        ├─ FMNetworkManager（Server，端口 3333）
        │                 └─ GameViewDecoder 图像数据
        │
        └─ WakeUpComputer ─ UDP 广播魔术包，端口 50000
```

## 4. 启动时自动连接的 TCP 设备

`FirstPageEquipManager.Start()` 会加载 `Equip.json`、`Relay.json` 和 `Red.json`，随后按顺序连接：

| 标识 | IP | 端口 | 类型 | 配置索引 |
|---|---|---:|---|---:|
| TCP80 | `192.168.86.80` | 10000 | 8 路继电器 | `RelayModelList[0]` |
| TCP81 | `192.168.86.81` | 10000 | 配置声明 1 路、报文数组含 8 路 | `RelayModelList[1]` |
| TCP82 | `192.168.86.82` | 10000 | 飞屏主机控制 | `RelayModelList[4]` |
| TCP85 | `192.168.86.85` | 10000 | 16 路灯光继电器 | `RelayModelList[2]` |
| TCP86 | `192.168.86.86` | 10000 | 16 路灯光继电器 | `RelayModelList[3]` |
| TCP90 | `192.168.86.90` | 502 | 八路红外模块 | `RedModelList[0]` |
| TCP91 | `192.168.86.91` | 502 | 单路红外模块 | `RedModelList[1]` |

连接实现为异步 `Socket.BeginConnect`。发送前把带空格的十六进制字符串转换为字节数组，再使用 `Socket.BeginSend` 直接发送；未发现 MBAP 头，因此虽然报文形态接近 Modbus RTU，实际承载方式是“RTU 风格帧直接跑 TCP”，不能直接认定为标准 Modbus TCP。

## 8. TCP 继电器协议

### 8.1 传输方式

- 协议承载：TCP 长连接。
- 报文格式：ASCII 配置中的十六进制字符串转为原始字节。
- 发送方式：单条直接发送；双条命令间隔 `0.3 秒`。
- UI 常用流程：连接 → 等待 `1 秒` → 发送。
- 接收：最多读取 1024 字节，日志只格式化前 9 字节；未实现严格响应帧解析、CRC 校验结果判断或设备状态机。

### 8.2 典型报文

现场 `Relay.json` 中主要为 `FE 05` 单线圈写入形式：

| 动作 | 报文 |
|---|---|
| 第 1 路开 | `FE 05 00 00 FF 00 98 35` |
| 第 1 路关 | `FE 05 00 00 00 00 D9 C5` |
| 第 2 路开 | `FE 05 00 01 FF 00 C9 F5` |
| 第 2 路关 | `FE 05 00 01 00 00 88 05` |
| 第 3 路开 | `FE 05 00 02 FF 00 39 F5` |
| 第 3 路关 | `FE 05 00 02 00 00 78 05` |
| 第 4 路开 | `FE 05 00 03 FF 00 68 35` |
| 第 4 路关 | `FE 05 00 03 00 00 29 C5` |
| 8 路全关 | `FE 0F 00 00 00 08 01 00 B1 91` |

注意：`Relay.json` 中 TCP80 的全开报文写成 `01 0F ... BE D5`，而通用模板写成 `FE 0F ... F1 D1`，从站地址和 CRC 不同，需以设备厂商协议或现场抓包确认。

## 10. 串口通讯

### 10.1 `PortControl`

- 当前 `level0` 未挂载。
- 默认参数：`COM3`、`9600`、`Parity.None`、`8 data bits`、`StopBits.One`，即常见的 `9600/8N1`。
- `OpenPortEvn()` 打开串口并启动接收线程。
- `WriteData(string)` 使用 `Encoding.UTF8` 写入字符串。
- 接收线程使用 1024 字节缓冲并输出日志，未看到业务协议解包。

### 10.2 `SerialPortControl`

- 当前 `level0` 未挂载，是静态串口工具类。
- 支持配置端口、波特率、校验位、数据位、停止位。
- 支持十六进制字符串与字节数组互转并发送。
- 接收逻辑未关联到当前展厅 UI，是否曾控制外部设备待确认。

## 11. FMNetwork、网络唤醒和其他网络代码

### 11.1 FMNetwork

`level0` 中 `FMNetworkManager` 当前配置：

- `AutoInit = true`
- `NetworkType = Server`
- 服务端监听端口：`3333`
- 客户端端口配置：`3334`

该模块更像画面流/数据同步工具，不属于继电器或红外协议，但新系统若要复用双屏画面传输，需要单独评估带宽、延迟和稳定性。

### 11.2 Wake-on-LAN

- 使用 UDP 广播端口 `50000`。
- 发送标准 102 字节魔术包：6 个 `FF` + MAC 地址重复 16 次。
- `Button_Click_WakeUp(string mac)` 可从 Unity 按钮传入 MAC。
- `ShutDown(string ip)` 通过 Windows `shutdown -s -m` 命令远程关机，需要目标 Windows 权限和防火墙允许。

## 13. 已发现的风险和不一致

| 级别 | 问题 | 影响 |
|---|---|---|
| 高 | `level0` 启动即连接多个旧 IP | 新现场可能持续连接失败、产生异常或延迟 |
| 高 | 四个不同网段混用 | 需要路由或多网卡，否则部分设备不可达 |
| 高 | 配置文件、硬编码地址和通用模板地址不一致 | 不能仅修改 JSON 就认为全部完成迁移 |
| 高 | 展柜开启和关闭使用不同 IP/端口 | 必须核对旧客户端部署方式 |
| 中 | TCP 报文为 RTU 风格原始帧，但跑在 TCP 上 | 不能用标准 Modbus TCP 客户端直接替代 |
| 中 | UDP 没有确认、重试、序号、超时或状态查询 | 无法保证大屏动作真正执行 |
| 中 | TCP 接收只打印，不解析设备状态 | UI Toggle 只能表示已下发，不能表示设备真实状态 |
| 中 | UDP 接收线程阻塞并使用 `Thread.Abort` | 退出、切换对象和异常网络下存在稳定性风险 |
| 中 | 红外开/关部分报文可能相同 | 可能是电源 Toggle 码，无法保证幂等 |
| 中 | 历史沿革拼接屏相同红外码连续发送两次 | 可能是旧现场补偿逻辑，需验证是否仍需要 |
| 低 | 命令大小写不统一，如 `AllOPen` | 新客户端必须完全按原字符串匹配，或统一升级协议 |
| 低 | 配置中的控制方式标签与实际通讯不完全一致 | 后台界面命名不能作为协议类型的唯一依据 |

## 14. 新自动讲解系统的处理建议

旧协议建议先保留为“兼容适配层”，不要让讲解业务直接调用 `TcpControl80`、`UDPClient` 等旧类。建议抽象为：

```text
讲解节点
  ├─ 画面动作：播放/暂停/切页/切场景
  ├─ 语音动作：播放/暂停/音量/TTS
  └─ 设备动作：继电器/红外/串口/TCP/UDP
                ↓
          统一 DeviceCommand
                ↓
    LegacyTcp / LegacyUdp / Serial / NewProtocol Adapter
```

每条新协议至少应配置：

- 设备唯一编号、展厅模块、设备名称
- 通讯类型、IP、端口或串口参数
- 开/关/查询指令及编码方式
- 超时、重试次数、重试间隔
- 成功响应规则、失败处理、离线状态
- 讲解时间点、画面动作、语音动作、设备动作
- 是否允许跳过、回退、重复执行和紧急停止
